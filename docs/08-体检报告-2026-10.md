# 体检报告与优化记录（2026-10-28）

这次把工具从头到尾跑了一遍：读代码、起服务、发请求、造脏数据、对官方文档。
下面按「多严重」排，每条都写了**现象、后果、现在怎么样**。

---

## 一、安全：三个真口子

### 1. `/api/open` 能打开本机任意路径（最严重）

原来这个接口留着一条兜底：

```python
else:
    target = req.get('path')      # 客户端传什么就打开什么
...
os.startfile(target)
```

**后果**：任何能往 `127.0.0.1:8848` 发请求的东西，都能让电脑执行一个 exe。
配合下一条，等于网页里一句请求就能启动程序。

**已修**：只允许打开工具目录（`E:\AI\Coopanion的宠物制作工具`）里的文件夹，
其它路径一律 400。传 `{"path": "C:\\Windows\\System32\\notepad.exe"}` 现在被拒。

### 2. 任何网页都能跨站触发这些接口

浏览器发「简单请求」不需要预检，`Content-Type: text/plain` 就能打到本机端口。
服务端只看 body 里的 JSON，不看是谁发来的。

**后果**：你开着工具的时候，随便打开一个恶意页面，它就能调删除项目、上传、打开路径。

**已修**：加了一层 `_local_only()`：Host 必须是 `127.0.0.1 / localhost`，
带 Origin 的必须是本机来源，POST 必须是 `application/json`。
实测伪造 `Host: evil.com` 和 `Content-Type: text/plain` 都返回 403。

### 3. 请求体没有上限

`_body()` 只按 `Content-Length` 读，多大都读。

**后果**：一个大文件就能把内存吃满，工具直接卡死崩掉。

**已修**：上限 96 MB，超了返回 413，并提示「大视频先压小或切段」。

### 4. API Key 明文放在会被扫描的目录（已改存储位置）

`studio\ai-config.json` 里是明文 Key。而这个文件夹是要给 AutoClaw 扫描的——
扫进去就等于 Key 进了 AI 的上下文。

**已改**：新保存的配置写到 `%LOCALAPPDATA%\PetPackStudio\ai-config.json`，
读取顺序是「环境变量 `PETSTUDIO_KEY` → 用户目录 → 老的 studio 文件」，
老的 Key 照样能用，不用重填。界面里从来不回显 Key，只显示"已保存"。

> 建议你自己做一步：确认新配置生效后，把 `studio\ai-config.json` 删掉。

## 二、功能：视频抽帧这条线基本不可用

### 5. 抽出来的帧根本不进"走路"分区

抽帧存成 `raw\clip_01.png`，而走路分区只认 `walk_f00.png` 这种名字。
`classify_assets()` 把它归到 `other`，`sync_raw_textures()` 也不认。

**后果**：抽完帧，走路还是原来的站立图，用户以为抽帧没生效。

**已修**：抽帧直接命名为 `walk_fNN.png`（接着已有编号往后排），抽完立刻同步进 `tex/`。

### 6. 抽出来的帧带整个背景，还是一张 1280×720 的大图

`fit_png()` 只做等比缩放和底部对齐，不裁边、不抠图。

**后果**：桌面上出现一块带背景的方块，人物只有指甲盖那么大。

**已修**：新增 `frame_to_walk()`：
从画面四边往里灌同色 → 背景清成透明 → 按不透明区域裁到人 → 底部对齐贴到 512 画布。

实测（用合成帧，白底和绿底各一张）：人物完整、底边对齐、没有方形背景块。

**已知局限**：白衣服 + 白背景会被一起抠掉一部分。所以容差默认调到 12，
并且支持 `bg: "none"` 关掉抠图只裁边。拍走路视频建议用**深色或纯绿背景**。

### 7. 没装 ffmpeg 时的提示等于没说

原来只回一句「装一个或直接上传截图」。

**已修**：明确给出三条路（winget 命令 / 重启 / 用截图代替），并在启动横幅里提前告诉你缺什么。

## 三、隐性坑：缺 Pillow 时静默降级

### 8. 没装 Pillow，一半功能会悄悄变差

`fit_png()` 在 `except Exception` 里返回 `False`，然后调用方直接 `copyfile`。
没有报错、没有提示，只是：表情生成失败、抠图失效、缩略图变成非方图。

**这台机器上就踩到了**：`python` 指向的 3.13 没装 Pillow，而 `Programs\Python\Python313` 装了。
双击 bat 用哪个解释器，决定了功能全不全。

**已修**：
- 启动横幅打印 `Python / Pillow / ffmpeg / node` 四项，缺了直接说缺什么、怎么装
- 新增 `/api/env`，网页顶部会出现一条黄色警告，写明缺什么 + 现成的安装命令

## 四、清单校验：和官方文档对完，补了三处

官方文档（`docs/characters.md`，API 2）里有几条硬限制，校验器原来没查：

| 补的规则 | 原来 | 现在 |
|---|---|---|
| `id` 不能是 `whale` | 只拦了 `coo` | 两个保留名都拦 |
| 文件条目 ≤ 2048 | 没查 | 超了报错 |
| 单文件 ≤ 16 MB | 没查 | 超了报错，并列出是哪个文件 |
| `figure.json` ≤ 256 KB | 没查 | 超了报错 |

另外把「不支持的图片扩展名」那行绕来绕去的写法（`.webp.replace(...)`）改成了一个明确的集合，
顺手加了 `.heic`——iPhone 拍的图经常是这个格式，之前不会提示。

### 9. 上传不验内容

原来只看扩展名，一段 base64 垃圾也会被改名成 `walk_f00.png` 写进 `tex/`。

**已修**：先看文件头（PNG/JPG/WEBP 的 magic bytes），再让 Pillow 真解一遍，
解不开就删掉并回报「内容不像 .png 图片」。

## 五、性能

### 10. 项目列表每次请求都全量校验

`GET /api/projects` 会对**每个**项目跑一遍 `validate_pack()`，
里面还要打开 PNG 跟模板逐像素比较。

**已修**：按 `figure.json / figure.js / tex / sounds` 的 mtime 做指纹缓存，
没动过就复用结果。实测 45 ms → 4 ms。

---

## 六、体验：加了一个预览页

### 11. 以前只能「装进 Coopanion」才知道长什么样

这是最大的缺口。做完包要导入、重启、看桌面，不满意再回来改，一轮好几分钟。

**已加**：`预览效果` 按钮 → `/preview?id=项目名`

- 站立 / 走路 / 坐着 / 睡觉 四种状态实时播
- 点表情看脸，`空格` 切走路，`1`~`9` 切表情
- 透明格 / 白底 / 黑底三种背景（壁纸颜色不同，效果差很多）
- 缺什么时候直接标红：没有走路帧就告诉你「走路会像贴纸在地上滑」
- 音效可以点着试听

预览读的是包里真实的 `tex/` 文件，不是另做的示意。

## 七、还没做，按值不值得排

### 值得做（我建议下一步就做这两个）

1. **表情标框可视化**。现在 `facegen.py` 靠 `face-layout.json` 手写四个坐标，
   换一张图就得重新量。可以在预览页上拖一个框，存回 `face-layout.json`，
   这是"一张图出全套"能不能普及的关键。
2. **`axes` / `presets` 换装**。官方支持多套配色/饰品的组合，面板上能直接切。
   我们的模板 `axes: []`，等于把这个能力浪费了。有了它，一个包能当三个用。

### 可以缓

3. **单张素材删除 / 改名**。现在只能设为主图，删错图只能去文件夹里删。
4. **AI 调用进度**。现在点完按钮静默等，最长 180 秒，用户会以为卡死。
5. **走路自然度**。程序变形出来的走路始终是"纸片人摆腿"。
   真正解决只能靠视频抽帧或多帧手绘，工具这边已经给了抽帧通道。
6. **侧面 / 背面**。素材只有正面时，转身是整组水平翻转，不是真背面。
   要真背面得补图，这不是代码能解决的。

### 明确不做

7. **自动装 Pillow / ffmpeg**。装软件属于改系统，必须你点头。
   工具只给命令，你自己决定装不装。

## 九、一句话总结

工具的逻辑是对的，问题集中在三处：
**门口没锁**（本机接口谁都能敲）、**视频那条路过不去**（抽帧不带背景处理也没进分区）、
**环境缺东西不吭声**（Pillow 一缺，静默降级）。

这三处都补上了，另外加了预览，让你不用装进 Coopanion 就能先看效果。
