# AI 提示词 · 备用平台通用版

积分用完了，或者想换个模型做，用这一份。

和 AutoClaw 版最大的区别：
不是所有平台都能读写你本地的文件。
所以这里分成两类提示词，先看清你在用哪种。

---

## 先判断你的平台属于哪类

| 能力 | 提示词用哪套 |
|---|---|
| 能读本地文件、能写文件、能跑命令 | 用 A 类，也能直接用 `03` 文档那份 |
| 只能聊天，输出文字 | 用 B 类，它给你内容，你自己存 |
| 能上网但读不了本地盘 | 用 B 类，把文件内容复制给它 |

右侧有文件上传的平台，把 `figure.json` 传上去再问，效果比纯聊天好。

---

## A 类 · 能操作文件的平台

```
帮我把一只 Coopanion 形象包做完。

工作目录：E:\AI\Coopanion的宠物制作工具

第一步先读，读完再动手：
docs\02-形象包格式规范.md
docs\01-制作流程总览.md
studio\templates\minimal-pack\figure.json

现状：
项目 id：<id>
主图：<路径>
已完成：<列出，比如：主图已放好>
要做：<列出，比如：改 about 和 vocab，然后打包>

约束：
- 不要改 figure.js 的渲染逻辑，它是验证过的模板
- figure.json 的 manifest/api/entry/export 必须是 2、2、"figure.js"、"createMyPet"
- vocab 的 id 只能用官方套件已有的，不要发明
- names 只写中文别名，不要英文，英文容易和 id 撞重名
- 别名不含逗号、顿号、空格、【】<>
- 每改一次清单必须跑校验：node studio\tools\test_pack.mjs projects\<id>\pack
- 不确定就说不确定

做完给我：改动清单、校验输出、zip 路径。
```

## B 类 · 只能聊天的平台

这种平台不能跑校验，所以你要自己把关。
好处是它输出快，适合批量写内容。

### B1 · 让它只输出 figure.json

```
你是 Coopanion 形象包的清单作者。只输出 figure.json 的完整内容，不要解释。

Coopanion v0.2.13 的格式规则（必须严格遵守）：

根对象必填字段：
- manifest: 数字 2
- api: 数字 2
- id: 匹配 ^[a-z0-9][a-z0-9-]{0,31}$，不能是 "coo"
- version: 字符串，如 "1.0.0"
- name: 对象，至少有 zh 键
- about: 对象，至少有 zh 键，写清形象
- entry: 固定 "figure.js"
- export: 固定 "createMyPet"
- vocab: 数组

其它字段按这个写：
- axes: []
- presets: []
- sounds: {}
- can: {"walk": true}
- thumb: "thumb.png"

vocab 每一项：
- id: 只能用 neutral happy wink love shy surprised angry sad sleepy thinking smug pout excited cry confused worried flustered scared determined jump nod shake spin sit sleep wave dance hop look turn bow shiver
- kind: 只能是 "expression" 或 "motion"
- names: {"zh":["别名"]}，只写中文
- about: {"zh":"这个表情看起来什么样"}，必须具体
- seconds: 大于 0，表情 0.9-1.5，动作 1.0-2.0

硬约束：
- 所有 id 和中文别名全局不能重复
- 中文别名不能含 逗号 顿号 空格 【】<> 这些字符
- 不要写英文别名。id 和别名会一起查重，英文写得和 id 一样就会整包被拒

我的宠物：<两三句话描述>

要求 18 个词，12 个表情 6 个动作。
只输出一个 json 代码块，不要别的文字。
```

拿到结果后自己存成 `projects\<id>\pack\figure.json`，然后用工具点「检查这一包」。

### B2 · 让它只写词表

```
只输出一个 JSON 数组，不要解释，不要代码块以外的任何字。

格式：
[{"id":"happy","kind":"expression","names":{"zh":["开心"]},"about":{"zh":"眼睛弯成 ^ ^"},"seconds":0.9}]

可用 id：
expression: neutral happy wink love shy surprised angry sad sleepy thinking smug pout excited cry confused worried flustered scared determined
motion: jump nod shake spin sit sleep wave dance hop look turn bow shiver

规则：
- 18 项，12 表情 6 动作
- 只写中文别名，不写英文
- 别名不含逗号顿号空格【】<>
- 所有 id 和别名互不重复
- about 要具体，写这个表情长什么样

宠物设定：<贴 about>
```

### B3 · 纯人工拼装

没有 AI 也能做。照 `02` 文档的第八节，手写 20 分钟的 JSON。
工具里的模板已经写好了 20 个词，直接改 `about` 和 `names` 就行。

## 画主图的提示词

这条是给画图工具的，不是给对话模型的。
Midjourney、即梦、可灵、GPT 图像、Nano Banana 都能用。

### 中文版

```
一只 <描述>，扁平插画风格，正面站立，全身，双手自然垂在身侧，
圆润的轮廓，粗描边，简洁的配色，
纯白背景，脚底贴着画面下边缘，主体水平居中，
画面上方留出约 15% 的空白，
正方形构图，主体占画面宽度的 75% 左右，
不要文字，不要阴影，不要背景元素，不要地面线
```

### 英文版（效果通常更好）

```
a <description>, flat illustration style, front view, full body, standing,
arms resting at the sides, rounded silhouette, thick clean outline,
simple limited palette, plain pure white background,
feet touching the bottom edge of the frame, subject horizontally centered,
about 15% empty space at the top, square composition,
subject fills about 75% of the frame width,
no text, no shadow, no background elements, no ground line
```

把 `<description>` 换成你的角色，例如：

- `round orange tabby cat with a chipped right ear`
- `small blue slime creature with big eyes`
- `chubby penguin wearing a tiny scarf`

### 生成完之后

1. 抠掉白底，存成透明 PNG。
   在线抠图站一分钟能搞定。
2. 检查脚底有没有贴边，没贴就裁。
3. 检查上方有没有留白，没有就补。

**不要指望 AI 一次画对。** 通常要生成四到十张挑一张。
挑的标准只有一条：作为一个 256 像素的小图，还认得出是什么。

### 表情图提示词

```
基于这张角色图，只改表情：<表情描述>。
保持其余所有部分完全不变 —— 同样的姿势、同样的身体位置、同样的比例、
同样的头发和服装、同样的描边粗细。
透明背景，正方形，1024x1024。
```

`<表情描述>` 的例子：
- `eyes curving into upward crescents, mouth slightly open in a smile`
- `eyes replaced by two small hearts, cheeks blushing`
- `eyes closed into flat lines, mouth open in a wide yawn`
- `eyes wide open with tiny pupils, mouth in a small o shape`
- `eyes squeezed shut, tears streaming down both cheeks, mouth wide open crying`

**AI 改出来的图几乎对不齐。** 你必须：
1. 把原图垫底，调成半透明。
2. 把 AI 的图叠上去，缩放到轮廓重合。
3. 只保留眼睛和嘴的部分，其余擦掉。

这一步人工不可省。

## 平台差异对照

| 平台 | 能读本地文件 | 能跑命令 | 建议 |
|---|---|---|---|
| AutoClaw 5.3 | 能 | 能 | 用 `03` 那份，效率最高 |
| Claude Code / Codex CLI | 能 | 能 | 用 A 类，效果和 AutoClaw 差不多 |
| Cursor / Trae | 能 | 能 | 用 A 类 |
| Claude / ChatGPT 网页版 | 不能 | 不能 | 用 B 类，内容自己存 |
| DeepSeek / 通义 / Kimi 网页版 | 不能 | 不能 | 用 B 类 |
| 带文件上传的网页版 | 能读你上传的 | 不能 | 把 figure.json 传上去，用 B 类 |

**判断标准很简单：** 它能不能自己执行 `node tools\test_pack.mjs`。
能，就用 A 类。不能，就用 B 类，校验你自己在工具里点。

---

## 一句话总结

不管换到哪：

**格式规范在 `docs\02`，模板在 `studio\templates`，校验用 `tools\test_pack.mjs`。**

这三个东西是平台无关的。AI 换多少个都一样。
